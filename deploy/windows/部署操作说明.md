# TCMP 用例管理平台 — Windows 服务器部署操作说明（方案 A：本机操作）

> 适用场景：把平台部署在一台 **Windows 服务器**上，**用 IP 局域网访问**（如 `http://192.168.20.127/`）。
> 所有步骤都在**服务器本机**操作，不需要远程连接。
> 全程预计 30~60 分钟。

---

## 〇、先准备这些东西

| 项 | 说明 |
|---|---|
| 一台 Windows 服务器 | Win10/11 或 Windows Server 2019/2022 均可，要有**管理员账号** |
| 项目代码 | 把整个 `用例管理平台` 文件夹拷到服务器，建议放在 `C:\tcmp\用例管理平台` |
| 联网 | 安装 Node、下载 nginx、`npm` 装依赖时需要联网（公司网若拦截见文末“常见问题”） |

> 下文统一假设代码在 `C:\tcmp\用例管理平台`。如果你放在别处，把命令里的路径相应替换即可。

---

## 一、安装基础软件（只需一次）

### 1. 安装 Node.js 20 LTS
1. 打开 https://nodejs.org/ ，下载 **20.x LTS** 的 Windows 安装包（`.msi`）。
   > ⚠️ 不要装 22/24 等更高版本，会导致前端构建报错。
2. 双击安装，一路下一步（保持默认，会自动加入 PATH）。
3. 验证：开“**PowerShell**”，输入：
   ```powershell
   node -v
   ```
   能看到 `v20.x.x` 即成功。

### 2. 下载 nginx for Windows
1. 打开 http://nginx.org/en/download.html ，下载 **Stable version** 的 `nginx/Windows-x.x.x`（zip）。
2. 解压到 `C:\nginx`（解压后里面应有 `nginx.exe`）。

> 这一步只是“下载解压”，先不用启动，后面步骤三会配置它。

---

## 二、构建前后端（普通 PowerShell 即可）

1. 开一个**普通 PowerShell**窗口（不用管理员）。
2. 进入部署脚本目录并运行构建脚本：
   ```powershell
   cd C:\tcmp\用例管理平台\deploy\windows
   powershell -ExecutionPolicy Bypass -File .\1-build.ps1
   ```
3. 脚本会自动：装后端依赖→编译后端→装前端依赖→构建前端。
   成功后会显示：
   ```
   Build done.
     backend:  ...\backend\dist\main.js
     frontend: ...\frontend\dist\index.html
   ```

> 如果 `npm ci` 报网络/证书错误，先看文末「常见问题①」配置镜像源，再重跑本步骤。

---

## 三、把后端注册成 Windows 服务（需要管理员）

> 这样后端会**开机自启、崩溃自动重启**，并自动生成安全的密钥。

1. **以管理员身份**打开 PowerShell：
   开始菜单搜 “PowerShell” → 右键 → **以管理员身份运行**。
2. 运行：
   ```powershell
   cd C:\tcmp\用例管理平台\deploy\windows
   powershell -ExecutionPolicy Bypass -File .\2-install-backend-service.ps1
   ```
3. 脚本会自动下载 NSSM（服务管理小工具）、安装名为 **`TCMP-Backend`** 的服务并启动它。
   最后会看到 `SERVICE_RUNNING` 和健康检查输出，表示后端已在 `127.0.0.1:3000` 跑起来了。

**以后管理后端服务**（管理员 PowerShell）：
```powershell
nssm restart TCMP-Backend   # 重启（更新代码后用）
nssm stop    TCMP-Backend   # 停止
nssm status  TCMP-Backend   # 查看状态
```
后端日志在：`C:\tcmp\用例管理平台\backend\logs\service.*.log`

> **127 等「计划任务托管后端」环境（可选）**  
> 若后端用 Windows 计划任务而非 NSSM，进程**正常退出**后可能不会自动拉起（曾导致 Nginx 502）。可额外注册 Watchdog 计划任务，每 3 分钟检测 `127.0.0.1:3000`，未监听则重启后端：
> ```powershell
> cd C:\tcmp\用例管理平台\deploy\windows
> python apply-resilience-127.py   # 需在目标机以管理员执行；脚本见 setup-backend-resilience-127.ps1
> ```
> 151 使用 NSSM（`AppExit=Restart`）时通常**不需要** Watchdog。

## 四、配置并启动 nginx（需要管理员）

1. 还在**管理员 PowerShell**里，运行：
   ```powershell
   cd C:\tcmp\用例管理平台\deploy\windows
   powershell -ExecutionPolicy Bypass -File .\3-setup-nginx-and-firewall.ps1
   ```
   这一步会：
   - 生成已填好前端路径的配置文件 `nginx-tcmp.generated.conf`
   - 放行 Windows 防火墙的 **80 端口**

2. **把配置接入 nginx**（二选一，推荐方式 A）：

   **方式 A：include（改动最小）**
   - 用记事本打开 `C:\nginx\conf\nginx.conf`
   - 在文件里 `http {` 这一行的**下面**，加一行（注意把路径换成你的实际路径）：
     ```
     include C:/tcmp/用例管理平台/deploy/windows/nginx-tcmp.generated.conf;
     ```
   - 同时把 nginx 自带的那个默认 `server { listen 80; ... }` 块**删掉或注释掉**（避免和我们的 80 端口冲突）。

   **方式 B：直接替换**
   - 用 `nginx-tcmp.generated.conf` 里的 `server { ... }` 整段，替换 `nginx.conf` 中自带的 `server { ... }` 段。

3. **启动 nginx**（普通或管理员 PowerShell 都行）：
   ```powershell
   cd C:\nginx
   .\nginx.exe              # 启动
   ```
   - 改过配置后重新加载：`.\nginx.exe -s reload`
   - 停止 nginx：`.\nginx.exe -s stop`

> nginx 启动后不会有窗口，属于正常。可用 `tasklist | findstr nginx` 确认进程在跑。

## 五、验证与访问

1. **在服务器本机**，浏览器打开：
   ```
   http://localhost/
   ```
   能看到登录页就说明前后端、nginx 都通了。

2. **查服务器 IP**（给同事用）：
   ```powershell
   ipconfig
   ```
   找 “**IPv4 地址**”，例如 `192.168.20.127`。

3. **同事在自己电脑**浏览器打开：
   ```
   http://192.168.20.127/
   ```
   （把 IP 换成上一步查到的实际地址）即可使用。

## 七、数据与备份（重要）

- 业务数据库文件：`C:\tcmp\用例管理平台\backend\data\tcmp.db`
- 自动滚动备份目录：`C:\tcmp\用例管理平台\backend\data\backups\`

## 八、日常维护速查

| 操作 | 命令（管理员 PowerShell） |
|---|---|
| 重启后端 | `nssm restart TCMP-Backend` |
| 看后端状态 | `nssm status TCMP-Backend` |
| 看后端日志 | 打开 `backend\logs\service.err.log` |
| 重载 nginx | `cd C:\nginx ; .\nginx.exe -s reload` |
| 停 nginx | `cd C:\nginx ; .\nginx.exe -s stop` |

### 更新到新版本代码时
1. 用新代码覆盖 `C:\tcmp\用例管理平台`（**保留** `backend\data\` 目录不要覆盖）。
2. 重新构建：`powershell -ExecutionPolicy Bypass -File .\1-build.ps1`
3. 重启后端：`nssm restart TCMP-Backend`
4. 重载 nginx（前端有变动时）：`cd C:\nginx ; .\nginx.exe -s reload`

## 九、常见问题

**① `npm ci` 报 SSL / 证书 / 网络错误（公司网络常见）**
在两个目录分别配置淘宝镜像后重试：
```powershell
npm config set registry https://registry.npmmirror.com
# 若是自签名证书拦截导致的 SSL 报错，可临时关闭校验（仅内网可信环境）：
npm config set strict-ssl false
```
然后重新运行 `1-build.ps1`。

**② 浏览器打开是 nginx 欢迎页 / 404**
说明 nginx 用的还是自带默认配置。回到**步骤四**，确认已 include 我们的配置、并删掉了自带的默认 `server` 块，再 `nginx.exe -s reload`。

**③ 同事电脑打不开，但服务器本机 `http://localhost/` 正常**
多半是防火墙或网段问题：
- 确认步骤三/四已放行 80 端口（脚本已自动加规则）。
- 确认同事电脑和服务器在**同一局域网/网段**，互相能 `ping` 通服务器 IP。

**④ 后端没起来（登录页能开但点登录报错 / 502 Bad Gateway）**
- 查 `backend\logs\service.err.log`。
- 重启：`nssm restart TCMP-Backend`（NSSM 环境）或重启对应计划任务。
- 确认 3000 端口在监听：`netstat -ano | findstr :3000`。
- 计划任务托管且进程已退出：检查是否已配置 Watchdog（见步骤三说明）。

**⑤ 端口被占用**
- 80 被占（常见是 IIS/Apache）：停掉占用方，或改 nginx 监听端口。
- 3000 被占：改后端端口——`nssm set TCMP-Backend AppEnvironmentExtra "NODE_ENV=production" "PORT=3001" "JWT_SECRET=<原值>"`，同时把 nginx 配置里的 `3000` 改成 `3001` 并 reload。

---

如遇到本说明未覆盖的问题，把对应的报错信息（尤其是 `backend\logs\service.err.log` 的内容）记下来即可定位。
